# Архитектура

```
 SessionWatcher ──(PID играющих приложений)──► ProcessLoopbackReader ─┐
 (опрос сессий + Toolhelp)                                            │  CaptureWorker (поток на источник)
 MicrophoneReader (NAudio, по желанию) ───────────────────────────────┘          │
                                                                                 ▼
                                                                    TrackStore  (TrackRing на приложение)
                                                                     │                       │
                                                         ReplaySaver (по хоткею)    ContinuousRecorder (поток-писатель)
                                                                     └──────► WavFileWriter ◄┘
```

## Модули Core

| Папка | Назначение |
|---|---|
| `Capture/` | Поиск играющих приложений и сам захват |
| `Audio/` | Общие часы, буфер по дорожкам, реестр постоянных слотов |
| `Output/` | Запись WAV, сохранение отката, непрерывная запись |
| `Config/` | Настройки (JSON) и пути |
| `Input/` | Модель хоткея («Ctrl+Alt+F10») |
| `Interop/` | Объявления COM для WASAPI |
| `AudioHub.cs` | Фасад: связывает всё выше и управляет жизненным циклом |

## Ключевые решения

**Захват по процессам.** Используется документированный режим *process loopback* в WASAPI (`ActivateAudioInterfaceAsync("VAD\Process_Loopback")` с `AUDIOCLIENT_ACTIVATION_PARAMS`). Приложение только называет PID — звук отдаёт сам аудиосервис Windows. Это работает независимо от того, на какое устройство вывода играет приложение.

**Общая шкала времени.** Все источники пишут в единую временную шкалу `FrameClock` (кадры 48 кГц от QPC). Пакеты получают позицию из временной метки WASAPI, а пауза между пакетами остаётся пустым местом. Благодаря этому дорожки выровнены между собой без какой-либо подгонки при сохранении.

**Буфер из 100-мс блоков.** `TrackRing` — кольцо блоков по 100 мс; блок, в который не попало ни одного ненулевого сэмпла, не выделяется вовсе (`null`). Запись в один блок суммируется с насыщением, поэтому несколько процессов одного приложения естественно сливаются в одну дорожку.

**Одно хранилище на два режима.** Непрерывная запись не захватывает звук сама. Она каждые 250 мс переносит уже накопленные в `TrackStore` блоки на диск с запаздыванием в 400 мс (чтобы запоздавшие пакеты успели появиться). Запись и откат поэтому всегда согласованы, а захват не дублируется.

**Склейка клипов.** `ReplaySaver` помнит последний клип (папку, кадр начала и конца, список файлов). Если новое сохранение попало в окно склейки, он открывает существующие файлы через `WavFileWriter.OpenForAppend` и дописывает только промежуток `[конец прошлого клипа, сейчас)`. Позиции в файлах отсчитываются от начала первого клипа, поэтому шов точен до кадра. Сначала открываются все файлы, и только потом начинается запись: если какой-то файл занят, ничего не изменено, и сохраняется отдельный клип. В конце все файлы дополняются до общей длины.

**WAV с «дырами».** `WavFileWriter` пишет по произвольной позиции: пропуск в записи превращается в `Seek` вперёд, а файловая система заполняет его нулями. Файл, который появился позже других, начинается с тишины и поэтому остаётся синхронным с остальными.

**Постоянные слоты.** `TrackRegistry` выдаёт приложению номер при первой встрече и сохраняет в `tracks.json`; номер не меняется и не переиспользуется. Он же стоит префиксом в имени файла.

**Исключение дублей.** Захват PID X включает его дочерние процессы. Если у процесса есть предок с тем же exe, который тоже играет, его захват пропускается (`CapturePlanner`), иначе звук удвоился бы.

## Потоки

- UI-поток (STA): трей, хоткеи (`WM_HOTKEY` на message-only окне), окно настроек.
- Все COM-вызовы WASAPI выполняются на потоках MTA (пул потоков, `session-watcher`, `capture:*`). `AudioHub` намеренно уводит такие вызовы из UI-потока.
- `session-watcher` опрашивает сессии раз в 750 мс; на каждое играющее приложение приходится один `capture:*`-поток.

## Тесты

`tests/AudioReplay.Tests` покрывает чистую логику: разбор хоткеев, кольцевой буфер (границы блоков, суммирование, вытеснение, изменение размера), заголовок WAV и пропуски, планировщик захвата (дубли, исключения, циклы PID), постоянство слотов, нормализацию настроек, а также сохранение отката и непрерывную запись на синтетическом звуке. Реальный звук проверяет `scripts/smoke-test.ps1`.
